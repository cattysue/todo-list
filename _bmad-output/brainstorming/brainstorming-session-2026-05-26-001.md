## 세션 개요

**주제:** Todo-list 프로젝트 기능 범위 및 설계 브레인스토밍
**목표:** 초보자 연습 프로젝트로서 적절한 기능 범위 탐색, 기능 우선순위 결정, 구현 전략 아이디어 도출

### 제안된 기능 목록

**기본 기능:**
- 할일 추가 (제목, 내용, 마감날짜)
- 할일 완료 체크
- 할일 삭제
- 할일 수정
- 목록 조회 (전체/완료/미완료 필터)

**추가 기능:**
- 우선순위 (높음/중간/낮음)
- 반복 설정 (없음/매일/매주)
- 스트릭 (연속 달성일)
- 주간 성취도 대시보드

### 세션 설정

**학습 목표:** Claude Code + BMAD 워크플로우를 이해하는 것 (todo-list는 실습 도구)
**제약 조건:** 시간 제한, 초보자, 혼자가 아닌 Claude Code와 함께 개발

## 기법 실행 결과

### Phase 1: Question Storming

**핵심 인사이트:**
- "기능이 너무 복잡한가?"라는 질문이 사실은 두 가지 질문이었음
  - 구현 난이도 문제 → Claude Code와 함께하면 많이 해결됨
  - 학습 효율성 문제 → 기능이 많을수록 BMAD 학습이 넓어지는가, 얕아지는가?
- **진짜 판단 기준 도출:** "BMAD 워크플로우를 배우기에 적절한 복잡도인가?"

### Phase 2: SCAMPER Method

**E(Eliminate) — 제거 결정:**
- 주간 성취도 대시보드 → 제거 (학습 목표와 무관, 구현 복잡)
- 스트릭(연속 달성일) → 제거 (날짜 추적 로직 불필요하게 복잡)
- 반복 설정(매일/매주) → 제거 (날짜 계산 로직이 가장 복잡한 기능, CRUD 학습에 불필요)

**M(Modify) — 단순화 결정:**
- 할일 추가 시 "내용(본문)" 필드 → 제거 (제목 + 마감날짜로 충분)

## BMAD 학습 관점에서의 적합성

- CRUD 전체 사이클 경험 가능 → PRD/설계/개발 흐름을 완전히 돌려볼 수 있음
- 우선순위 기능이 단순 CRUD보다 조금 더 복잡한 설계 경험을 제공
- 복잡한 날짜 로직 없이 제한된 시간 내 완성 가능
- 기능 수가 적어 BMAD 도구의 출력물을 검토하고 이해하기 용이
