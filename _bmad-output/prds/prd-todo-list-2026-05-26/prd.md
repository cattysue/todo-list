# PRD: Todo List App

## 0. 문서 목적

이 PRD는 Claude Code + BMAD 워크플로우 학습을 위한 Todo List 웹 애플리케이션의 요구사항을 정의합니다. 대상 독자는 개발자(Catty) 본인이며, 이 문서를 기반으로 아키텍처 설계 및 개발 스토리가 도출됩니다. 핵심 용어는 §3 용어집에 정의되며 이후 섹션에서 동일하게 사용됩니다.

---

## 1. 비전

Todo List App은 개인 할일을 웹 브라우저에서 관리할 수 있는 단일 사용자용 웹 애플리케이션이다. 사용자는 할일을 추가·수정·삭제하고, 완료 여부와 우선순위로 목록을 관리하며, 원하는 항목만 필터링하여 볼 수 있다.

이 앱의 주된 목적은 Next.js(프론트엔드) + FastAPI(백엔드) + Supabase(데이터베이스) + Railway(배포) 스택으로 구성된 풀스택 웹 개발 사이클을 경험하고, Claude Code와 BMAD 워크플로우가 실제 개발에서 어떻게 작동하는지 익히는 것이다.

## 2. 대상 사용자

### 2.1 주요 페르소나

**Catty** — Claude Code와 BMAD를 활용한 풀스택 웹 개발을 처음 배우는 학습자. 이 앱을 직접 사용하면서 동시에 만드는 제작자이자 사용자.

### 2.2 해결하는 과제 (JTBD)

- 오늘 해야 할 일을 빠르게 기록하고 싶다
- 마감날짜와 우선순위로 무엇을 먼저 할지 파악하고 싶다
- 완료한 일과 남은 일을 구분해서 보고 싶다

### 2.3 핵심 사용자 여정

- **UJ-1. 할일 추가 및 우선순위 설정** — Catty가 앱에 접속해 새 할일(제목, 마감날짜, 우선순위)을 입력하고 저장한다. 저장 즉시 목록에 나타난다.
- **UJ-2. 완료 처리 및 필터 조회** — Catty가 완료한 할일을 체크 표시하고, 필터를 "미완료"로 전환해 남은 할일만 확인한다.

## 3. 용어집

- **할일(Todo)** — 제목, 마감날짜, 우선순위, 완료 여부로 구성된 단일 작업 항목.
- **우선순위(Priority)** — 할일의 중요도. 높음(High) / 중간(Medium) / 낮음(Low) 세 단계.
- **마감날짜(Due Date)** — 할일을 완료해야 하는 날짜. 선택 입력.
- **완료 상태(Status)** — 할일의 처리 여부. 완료(Complete) 또는 미완료(Incomplete).
- **필터(Filter)** — 완료 상태 기준으로 목록을 좁혀 보는 기능. 전체 / 완료 / 미완료.

## 4. 기능

### 4.1 할일 추가

**설명:** 사용자가 새 할일을 생성한다. 제목은 필수, 마감날짜와 우선순위는 선택 입력이다. 저장 후 목록에 즉시 반영된다. UJ-1을 실현한다.

**기능 요구사항:**

#### FR-1: 할일 생성
사용자는 제목을 입력하여 할일을 생성할 수 있다.

**검증 조건:**
- 제목이 비어 있으면 저장이 불가하고 오류 메시지가 표시된다.
- 저장 성공 시 새 할일이 목록 상단 또는 하단에 나타난다. *(생성 순 정렬)*
- 마감날짜를 입력하지 않아도 저장할 수 있다.

#### FR-2: 우선순위 기본값
할일 생성 시 우선순위를 지정하지 않으면 기본값은 **중간(Medium)**으로 설정된다.

**검증 조건:**
- 우선순위 미선택 저장 시 DB에 Medium으로 기록된다.

---

### 4.2 할일 완료 체크

**설명:** 사용자가 할일 항목에서 완료 여부를 토글한다. 완료된 항목은 시각적으로 구분된다(예: 취소선). UJ-2를 실현한다.

**기능 요구사항:**

#### FR-3: 완료 상태 토글
사용자는 할일의 완료 상태를 완료↔미완료로 전환할 수 있다.

**검증 조건:**
- 토글 즉시 UI에 반영되고 DB 상태가 업데이트된다.
- 완료 항목은 취소선 등 시각적 구분이 적용된다.
---

### 4.3 할일 삭제

**설명:** 사용자가 불필요한 할일을 영구 삭제한다.

**기능 요구사항:**

#### FR-4: 할일 삭제
사용자는 할일을 삭제할 수 있다.

**검증 조건:**
- 삭제 후 목록에서 즉시 제거된다.
- 삭제는 영구적이며 복구 기능은 제공하지 않는다.
---

### 4.4 할일 수정

**설명:** 사용자가 기존 할일의 제목, 마감날짜, 우선순위를 변경한다.

**기능 요구사항:**

#### FR-5: 할일 편집
사용자는 할일의 제목, 마감날짜, 우선순위를 수정할 수 있다.

**검증 조건:**
- 수정 후 저장 시 목록에 즉시 반영된다.
- 제목을 비워두고 저장하면 오류 메시지가 표시된다.

---

### 4.5 목록 조회 및 필터

**설명:** 사용자가 전체 할일 목록을 조회하고, 완료 상태로 필터링한다. UJ-2를 실현한다.

**기능 요구사항:**

#### FR-6: 전체 목록 조회
사용자는 저장된 모든 할일을 목록으로 볼 수 있다.

**검증 조건:**
- 페이지 진입 시 전체 할일이 표시된다.

#### FR-7: 상태 필터
사용자는 전체 / 완료 / 미완료 중 하나를 선택해 목록을 필터링할 수 있다.

**검증 조건:**
- 필터 선택 즉시 해당 조건의 항목만 표시된다.
- 기본 필터는 "전체"다.
---

### 4.6 우선순위

**설명:** 각 할일은 높음(High) / 중간(Medium) / 낮음(Low) 우선순위를 가진다. 생성 및 수정 시 설정 가능하며, 목록에서 우선순위가 시각적으로 표시된다.

**기능 요구사항:**

#### FR-8: 우선순위 표시
목록에서 각 할일의 우선순위가 시각적으로 구분되어 표시된다(예: 색상 배지).

**검증 조건:**
- 높음 / 중간 / 낮음이 서로 다른 시각적 표현으로 구분된다. `[ASSUMPTION: 색상 배지]`
